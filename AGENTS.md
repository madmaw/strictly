## Commenting

- When making a branch or pull request, when you add a comment, consider if the comment is describing the diff or if it is describing the code. If it is describing the diff then that comment will lose context the second the PR merges and then becomes misleading or meaningless. Comments in the code should describe the code in its current form.
- Self-documenting code (for example, types with descriptive names or structures) is preferred to comments where possible.
- Comment only when necessary.
